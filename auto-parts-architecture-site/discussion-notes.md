# 汽车零配件门店备补货业务架构讨论沉淀

日期：2026-05-28

## 1. 对业务架构的共识

业务架构不是简单画模块图，也不是系统架构图、流程图或组织架构图。它要回答：

```text
公司/业务到底要做什么？
靠哪些业务能力做成？
这些能力之间怎么协同、怎么落地、怎么迭代？
```

业务架构的核心价值是：

1. 统一业务共识。
2. 明确业务边界。
3. 将业务目标翻译成业务能力。
4. 串起业务主链路。
5. 指导流程设计、系统建设、组织分工和运营机制。
6. 指导分阶段建设优先级。

## 2. 本项目的业务背景

当前已有交易平台能力，包括：

- 询价
- 报价
- 下单
- 订单
- 履约
- 售后

本次业务架构不是重建交易平台，而是在已有交易平台基础上，新增和强化汽车零配件门店备补货业务能力。

核心建设对象是：

```text
商品选择 + 数量计划 + 供应商选择 + 采购补货 + 门店库存前置 + 平台交易协同 + 评价迭代
```

## 3. 业务架构要回答的核心问题

讨论过程中明确：

```text
“备什么、备多少、向谁备、怎么评价”是业务架构要回答的问题，
不是业务架构的分块分类标准。
```

因此业务架构不能机械拆成四张图，也不能简单按四个问题分层，而应该用完整业务能力体系承载这些问题。

### 3.1 备什么

解决：

```text
我要选哪些东西去备、去卖？
```

涉及：

- 选哪些品类
- 选哪些 OE / 车型适配件
- 选哪些品牌
- 选什么品质
- 选什么价格带
- 是否战略品牌
- 是否套件/单件
- 是否适合城市店/下沉店前置备货

关键输入：

- 历史交易
- 询价需求
- 缺货流失
- 城市消费等级
- 区域车型保有量
- 商品适配数据
- 供应商品牌合作
- 售后质量数据
- 人工线下经验

关键输出：

- 备货商品池
- 区域选品池
- 门店铺货商品清单
- 品牌/品质/价格带组合
- 替代商品
- 不建议备货清单
- 人工复核清单

### 3.2 备多少

解决：

```text
每个商品、每个区域、每个门店应该备多少数量？
```

涉及：

- 首铺量
- 补货量
- 安全库存
- 补货点
- 调拨量
- 清退量

关键输入：

- 历史销量
- 销量预测
- 询价热度
- 缺货机会
- 区域车型保有量
- 车龄结构
- 单车用量
- 套件/单件换算
- 箱规/MOQ
- 补货周期
- 门店等级

关键输出：

- 首铺数量
- 安全库存
- 补货点
- 补货建议
- 调拨建议
- 清退建议

### 3.3 向谁备

解决：

```text
向哪些供应商买？谁供这个商品最合适？
```

涉及：

- 供应商准入
- 供应商分层
- 主供/备供
- 品牌合作
- 区域供应能力
- 价格策略
- 交期策略
- 质量策略
- 售后责任

关键输入：

- 供应商价格
- 库存深度
- 交期
- 供货稳定性
- 质量表现
- 售后政策
- 区域服务能力
- 品牌合作政策

关键输出：

- 推荐供应商
- 主供/备供方案
- 采购来源
- 替代供应方案
- 供应商分层

### 3.4 怎么评价

解决：

```text
备得好不好？卖得好不好？供应商选得合不合适？流程是不是 OK？
```

评价维度：

- 选品评价
- 数量评价
- 供应评价
- 库存评价
- 经营评价
- 流程评价

关键指标：

- 选品命中率
- 动销率
- 缺货率
- 现货率
- 库存周转
- 滞销率
- 毛利率
- 售后率
- 错配率
- 到货及时率
- 供应商质量问题率
- 补货效率
- 调拨效率

评价结果要反向修正：

- 商品选择策略
- 补货参数
- 供应商评分
- 门店铺货策略
- 人工经验规则

## 4. 好的业务架构应该包含什么

一张好的业务架构图至少应该包含：

1. 业务目标
2. 业务边界
3. 业务对象
4. 业务能力
5. 业务主链路
6. 关键决策机制
7. 评价指标
8. 分阶段落地路径

## 5. 本项目推荐的业务架构表达方式

最终建议采用：

```text
业务目标 + 业务边界 + 业务对象 + 主链路 + 关键决策点 + 能力域 + 评价闭环 + 落地指导
```

而不是简单按问题拆图。

推荐主线：

```text
业务目标
↓
业务边界：已有交易平台 + 新增备补货能力
↓
业务对象：车型/OE/商品/品牌/门店/供应商/库存
↓
业务主链路：
数据输入 → 商品与适配底座 → 备什么 → 备多少 → 向谁备 → 采购补货与门店铺货 → 平台交易履约 → 评价反馈
↓
业务能力支撑：
商品选择能力、数量计划能力、供应商选择能力、采购补货能力、门店库存能力、平台协同能力、评价迭代能力
↓
落地指导：流程、系统、组织、运营、指标
```

## 6. 设计原则

### 6.1 不重建已有交易平台

已有询价、报价、订单、履约、售后能力作为基础平台能力复用。

新增重点是：

```text
门店备补货能力、商品选择能力、数量计划能力、供应协同能力、库存前置能力、评价迭代能力。
```

### 6.2 关键问题是决策点，不是分类标准

“备什么、备多少、向谁备”应该作为主链路中的关键决策点出现，而不是作为业务架构的一级分类。

### 6.3 用能力域承载业务，用主链路串起能力

业务架构既要有完整能力，也要有业务流动关系。

核心表达：

```text
用能力域承载业务，用主链路串起能力，用关键决策回答问题，用评价闭环驱动迭代。
```

### 6.4 评价体系必须反向闭环

评价不是事后报表，而是策略迭代机制。

评价结果必须回流到：

- 商品选择
- 数量计划
- 供应商选择
- 门店库存
- 补货参数
- 人工经验规则

## 7. 后续图形化表达建议

正式图建议包含以下区域：

1. 顶部：业务目标
   - 提升现货率
   - 降低缺货
   - 提升周转
   - 提升平台转化
   - 支撑城市店/下沉店铺货
   - 支撑战略品牌落地

2. 左侧/上层：业务边界
   - 已有交易平台能力
   - 新增备补货能力

3. 中间：主链路
   - 数据输入
   - 商品与适配底座
   - 关键决策一：备什么
   - 关键决策二：备多少
   - 关键决策三：向谁备
   - 采购补货与门店铺货
   - 平台交易履约
   - 评价反馈

4. 下层：能力域
   - 数据与业务输入
   - 商品与适配基础
   - 商品选择策略
   - 数量计划与补货策略
   - 供应商选择与采购协同
   - 门店库存与履约协同
   - 评价与策略迭代

5. 底部：落地指导
   - 流程设计
   - 系统建设
   - 组织分工
   - 运营机制
   - 指标体系
